The programming language for agents

Staal is a statically typed language for the code an AI agent runs to act: sending messages, moving money, changing records. A program can act only through capabilities granted when a run starts, must validate a model's answer before using it, has its model calls bounded at compile time, and journals every action, so an interrupted run resumes without performing a finished action again.

pip install staal
npm install @staal/node
curl -fsSL https://raw.githubusercontent.com/laurells/staal/main/install.sh | sh

The Python package, the Node.js package, or the staalc command alone. Each includes the compiler and runtime, with no Rust needed, on Linux (x86_64, arm64) and macOS (Apple Silicon, Intel). Other platforms build from source.

Features

What the compiler and runtime enforce

Each of these is a rule of the language, checked by the compiler or enforced by the runtime on every program, including the packages it imports. The error codes are the compiler's.

E002 · E003

Capabilities

An action needs a cap parameter, granted by whoever starts the run. Limits on money per action (each) and in total (max), on attempts (uses) and on targets (only) are checked by the runtime before the service is called. Code can narrow a capability, never widen it.

E001 · E006 · E007

Checked model output

A model's answer is Proposed<T> and cannot be used until validate checks it against T. Text from outside is untrusted: it reaches a model as data, never as its instruction, and never becomes SQL. Data marked @blind cannot reach a model.

E004 · E005

Bounded model use

A function declares budget(calls: N, tokens: N), and the compiler checks that its worst case fits, counting loops and calls. A model call cannot sit in an unbounded loop.

Journal

Durable runs

With a journal, every action, model call, clock read and random number is recorded before and after it happens. staalc resume replays what finished. An action that may or may not have happened is sent again with the same idempotency key when its grant says the service deduplicates by it; otherwise the run stops for an operator (staalc resolve).

Money

Exact money

Money is an exact amount in a currency's minor units, in ten currencies, read from decimal strings, never floats. Arithmetic never rounds or converts; adding or ordering amounts in two currencies fails.

Engines

Interpreter and native code

Programs run on an interpreter, or with their pure functions compiled to native code through Cranelift. The tests require identical results, failures, logs and journals from both. staalc build makes a standalone executable (Linux).

Examples

What it looks like

These programs are from the tutorial. The test suite runs every one of them and checks every output shown.

Ask a model

propose asks for a Reply. The instruction is text the program wrote; the customer's question goes in as data. validate checks the answer's shape before it is used, and budget bounds the function's model use.

support.staalcompiles
type Reply { answer: Text }

const POLICY = "Answer the customer's question about their order in one friendly sentence."

fn main(question: Text) -> Text budget(calls: 1, tokens: 500) {
    let reply = validate propose(Reply, instruct: POLICY, data: [question], tokens: 500)
    return reply.answer
}

Act within a grant

sms: cap sms.send(uses: 10) declares that the function sends at most ten messages. The run config grants the capability, and can grant less: here it grants one, so the second message is refused before it is sent.

remind.staalone message granted
type Customer { name: Text, phone: Text }

fn main(customers: List<Customer, 10>, sms: cap sms.send(uses: 10)) -> Int {
    let sent = 0
    for c in customers {
        let receipt = sms.send(c.phone, "Hi " + c.name + ", your order is ready.")
        set sent = sent + 1
    }
    return sent
}

Integrations

Programs as tools for your app and your agents

An app opens a program as a tool and calls it again and again. The app computes each call's grants from its own records, so a model's arguments are only ever inputs. Across calls, a tool keeps quotas (calls and money in a time window, each call holding its worst case until it ends), once (a repeated operation is one run), and app inputs (values only the app supplies, left out of the model's schema). The same host serves Python, Node.js, C, and the staalc mcp server.

A tool in Python

A standard customer may be refunded up to 50 USD at a time, a gold one up to 500. The model never sees the grants, and a tier the policy does not name gets no refund.

Adapters give the same tool to an agent framework: the OpenAI Agents SDK, LangGraph, the Vercel AI SDK, the Claude Agent SDK and Google's Agent Development Kit. Each has a tutorial whose files and outputs the tests check.

tools.pypip install staal
import staal

LIMITS = {"gold": "500.00", "standard": "50.00"}  # USD per refund, decided by the app


def grants(customer):
    # A tier the policy does not name gets no refund at all, and says why.
    limit = LIMITS.get(customer.get("tier")) if isinstance(customer, dict) else None
    if limit is None:
        raise PermissionError(f"no refund policy for this customer: {customer!r}")
    return {"pay": {"cap": "payments.refund", "uses": 1,
                    "each": {"amount": limit, "currency": "USD"}}}


refund = staal.Tool("refund.staal", name="refund_order",
                    description="Refund part of an order to the customer's original payment.",
                    grants=grants, journals="runs")
>>> print(refund({"order": "4417", "amount": {"amount": "80.00", "currency": "USD"}}, context={"tier": "standard"}).text)
'payments.refund' allows at most 50.00 USD per action; this action needs 80.00 USD

docs/GUARANTEES.md states each guarantee, what it depends on, how it is tested and where it stops, shown on a finance agent (examples/finops) whose attack suite is judged by its stand-in bank's own ledger.

The safety rules

Eight checks before anything runs

A program that breaks any of these is rejected with its error code and the line and column where it happens. The test suite holds 628 programs that must be rejected and 54 that must compile.

CodeRefused when
E001A model's answer reaches an action or a return without validate
E002An action is performed without a matching capability in scope
E003A capability is passed, assigned or returned with more authority than it holds
E004A function's worst-case model use can exceed its declared budget
E005A model call is inside an unbounded loop
E006An untrusted value is used as a model instruction or as SQL
E007Blinded data can reach a model, or decide whether a model call happens
E008A function claims it finished, citing evidence that is not proof of its own work

Status

Platforms and limits

Staal is a preview. Before 1.0, a minor version may change the language or its file formats, and the changelog says when one does (0.26.0 did).

Supported

  • Linux (x86_64, arm64) and macOS (Apple Silicon, Intel): CI runs the whole test suite on all four on every change
  • Python and Node.js packages, and the C interface (include/staal.h)
  • Model calls from Staal code through Claude (Anthropic's Messages API), or a scripted provider for tests; agent frameworks use any model they support and call Staal programs as tools
  • HTTP, files, TCP, SQLite and PostgreSQL as capabilities, and capabilities written in Staal over HTTP

Not yet

  • Windows, Linux with musl, and WebAssembly
  • staalc build and SQLite outside Linux
  • Runs against the live services (Claude, Termii, Stripe, Resend, Slack) with real keys; they are tested against local stand-ins
  • Other model providers in propose
  • An independent security review
  • Checking what C code does: runs that call C functions are marked unchecked

Get started

A first run from your app

The app decides the policy, here a refund limit per customer tier, and the runtime enforces it. No account or key is needed: with no payment service configured, the runtime uses a simulated one. These files are examples/quickstart/, and the test suite checks the output below.

refund.staalthe part that moves money
// Refunds an order, never by more than the app allows.
fn main(order: Text, amount: Money, pay: cap payments.refund(each: 500 USD)) -> Text {
    let receipt = pay.refund(order, amount)
    return "Refunded " + to_text(amount) + " for order " + order
}
app.pypip install staal
# pip install staal, then: python3 app.py
import os

import staal

lib = staal.Library()
PROGRAM = os.path.join(os.path.dirname(os.path.abspath(__file__)), "refund.staal")
LIMIT = {"gold": 500, "standard": 50}  # USD per refund, decided by your app


def refund(tier, order, amount):
    return lib.run(PROGRAM, {
        "entry": "main",
        "inputs": {"order": order, "amount": {"amount": amount, "currency": "USD"}},
        "grants": {"pay": {"cap": "payments.refund", "each": {"amount": str(LIMIT[tier]), "currency": "USD"}}},
    })


print(refund("standard", "4417", "35.00")["result"])
print(refund("standard", "4417", "300.00")["failure"]["message"])
app.jsnpm install @staal/node
// npm install @staal/node, then: node app.js
const path = require('path');
const staal = require('@staal/node');

const PROGRAM = path.join(__dirname, 'refund.staal');
const LIMIT = { gold: 500, standard: 50 }; // USD per refund, decided by your app

function refund(tier, order, amount) {
  return staal.run(PROGRAM, {
    entry: 'main',
    inputs: { order, amount: { amount, currency: 'USD' } },
    grants: { pay: { cap: 'payments.refund', each: { amount: String(LIMIT[tier]), currency: 'USD' } } },
  });
}

(async () => {
  console.log((await refund('standard', '4417', '35.00')).result);
  console.log((await refund('standard', '4417', '300.00')).failure.message);
})();
